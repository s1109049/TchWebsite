## 實測內容

`npm run build` 產生原版主結構的單一 HTML。

`npm test`：1 項版面結構契約檢查及 20 項 Chromium 瀏覽器情境測試全部通過，共 21 項。

瀏覽器情境包括：

1. 修改、切頁、重新讀取後登入、再修改流程；新增不丟字；詳情單欄保存；刪光流程後重開仍為空。
2. 匯出 HTML 在全新儲存空間開啟，後台先鎖定，登入後仍能修改；引號及腳本結束符號作為文字保存。
3. 兩個儲存按鈕連續更新同一個檔案，只選檔一次，沒有自動下載另一份 HTML。
4. 透過真正的瀏覽器 FileSystemFileHandle 寫入 OPFS 測試檔，控制代碼存進 IndexedDB；重新整理後恢復並再次寫入，無須重新開啟選檔器。
5. 拒絕權限、取消選檔、磁碟寫入失敗時，保留內容與未儲存提示。
6. 匯入舊 HTML 的內嵌資料，不執行其 script；引號姓名及習作可操作，重開後保留流程。
7. 跑馬燈、輪盤、夾公仔共用一輪名單；不重複、零剩餘不自動重新抽選、按重置才能重開一輪。
8. 輪盤及夾公仔實際動畫完成前停用模式／重置，結束後顯示大字結果，不用彈窗公布結果。
9. 語言、計時、歷史及範本在原有五個分頁仍可使用。
10. 無效匯入不覆蓋好資料；不支援直接寫入時不假裝更新原檔，另有明確下載副本流程。
11. 寫入期間的新修改不會被誤標為已保存；下一次儲存才更新新版本。
12. 匯入資料建立獨立識別碼；空白範本與已含個人資料的 HTML 都能在匯入後重新讀取，保留新班級流程。

## 驗證邊界

雲端的受管理 Chromium 禁止 `file://`，因此以靜態伺服器及攔截器載入實際 HTML 驗證程式。未調整瀏覽器管理政策。

OPFS 是瀏覽器私有檔案系統：它驗證真正檔案控制代碼的寫入、序列化保存及重開後恢復，並不等於已連接實體 USB。USB 選檔器、學校電腦政策、檔案鎖定及權限到期仍須在使用電腦確認。取消及拒絕權限等錯誤路徑另用測試替身驗證。

原版 Google Fonts 外部載入保留，測試會攔截字型請求以使用系統備援；沒有宣稱離線時已載入 Google 圓體。未測試 Safari／Firefox 直接寫檔，也未宣稱所有平台都不會要求再次授權。
